01 · OVERVIEW

What CanFirst-AI is

Canadian manufacturers, retailers and public buyers rely heavily on U.S. inputs. When tariffs or trade disputes hit, they need fast answers: what are we exposed to, can a Canadian company make this, and what happens if we switch? Today that research takes weeks of spreadsheets, trade databases and phone calls.

CanFirst-AI turns that into one guided flow. A user searches a company, industry, product, material or HS code. The platform maps the dependencies, searches Canada first, adds global Plan B suppliers, and runs the numbers on a switch, showing every trade-off along the way.

Before looking abroad, understand whether Canada can supply it, and understand the consequences before making the decision. CanFirst-AI is not "buy Canadian at any cost". A Canadian supplier is investigated first but never assumed to be best. The final decision always belongs to the user.

Who it is for

  • Procurement and supply-chain teams at Canadian companies facing tariff exposure.
  • Economic development and industry associations looking for import-substitution opportunities.
  • Policy analysts and public buyers who need neutral, sourced trade-offs rather than advocacy.

05 · ARCHITECTURE

How it works

The rule behind the design: AI researches, code calculates. Language models find and classify information. Every percentage, tariff, landed cost, carbon figure and scenario comes from deterministic code that gives the same answer every time.

Technology

  • Frontend: Next.js 15 (App Router), React 19, TypeScript. Charts, the map and the supply-chain graph are hand-drawn SVG, so there are no chart libraries to break.
  • Backend: Next.js API routes on Node. /api/research runs live research and /api/agents/test checks provider keys.
  • State: one shared in-memory store, so the supplier choice and mix carry across the company page, Scenario Lab and Reports.
  • Data sources: a common adapter interface (lib/sources.ts), so Statistics Canada, Trade Data Online, CBSA and others can be plugged in without touching the UI.

07 · CALCULATION ENGINE

The numbers, and how they are made

All maths lives in lib/calc.ts. The formulas below are shown in the app next to the results, and every input can be changed in the Scenario Lab.

Landed cost per tonne

product price × commodity index
+ freight per tonne × freight multiplier
+ tariff  = price × applied tariff %
+ insurance = price × insurance %
+ brokerage and customs (flat per tonne)
+ currency impact = price × (FX risk % + FX shock %)
+ carbon cost = carbon price × (production + transport CO2e per tonne)
+ switching cost ÷ (3 years × annual volume)
= ESTIMATED LANDED COST

08 · LIVE RESEARCH

How a live search works

  1. You search a company, product, material or HS code. The server cleans the input (160 characters maximum) and limits each user to 6 searches a minute.
  2. The AI researches with web search. A strict brief tells it to prefer Tier 1 sources, never invent companies, prices or tariffs, cite a source for every claim, grade product match honestly and stay politically neutral.
  3. Structured results come back as JSON: subject, inputs, Canadian suppliers, Plan B, tariffs, unknowns and sources. The server rejects malformed output instead of guessing.
  4. The Red Team check runs in code. Every claim is compared against the pages the AI actually retrieved during the search.
  5. You see the results with labels, clickable source numbers, the count of claims checked and downgraded, and an export button.

Red Team rules

If a claim…Then
cites no source"Verified fact" becomes INFERRED, confidence drops to Low
cites a page that was not actually retrieved in the search"Verified fact" becomes INFERRED, High confidence drops to Medium
is a supplier with no sourceProduct match is forced to Unverified
comes from a provider without web search (Grok in this app)Nothing can be marked Verified. Results come from model memory and are labelled that way.

09 · MULTI-AGENT DESIGN

The 12 agents

The platform is designed as a team of specialists. Each one can be given its own provider and model in Agent Settings.

AgentResponsibility

TradeHS codes, NAICS, trade flows, tariffs, agreements
Canadian SupplierCan Canada supply it first? Product fit, location, certifications, capacity
Global SupplierPlan B outside Canada and the current supplier country
FinancialLanded cost, FX, switching and 3-year impact (uses the calculation engine)
ClimateProduction and transport CO2e
EconomicImport substitution, regional activity, employment scenarios
CommunityWorkers, regions, skills, Indigenous economic and consultation considerations where evidence supports it
Policy & GeopoliticalTariffs, sanctions, export controls, chokepoints. Separates current policy from future scenarios.

Current build: live search runs the research roles as one AI request, and the Red Team runs as deterministic code. The Agent Room shows the full 12-agent story for the demo company as an animation. Splitting live research into separate agent calls is on the roadmap.
10 · SETUP

Install and run

  1. Install Node.js (LTS version) from nodejs.org.
  2. Unzip canfirst-ai.zip and open the folder in VS Code with File → Open Folder.
  3. Install packages. Open Terminal → New Terminal and run:
    npm install
  4. Start the app and open http://localhost:3000:
    npm run dev
  5. Optional, for Live mode: copy .env.example to .env.local, paste one API key, then stop the app with Ctrl + C and run npm run dev again.
  6. Check the key in Agent Settings with Test Connection, then run a practice search on Live Research. If you see "model not found", edit the model box next to the provider.

12 · SECURITY

Security and privacy

  • API keys are read only on the server from .env.local and never included in the browser bundle. That file is excluded from Git.
  • Session keys typed in Agent Settings stay in the tab's memory, are masked, are used only for the connection test, and disappear on reload.
  • Search input is length-limited and stripped of control characters. AI output is parsed into a fixed shape, and unexpected fields are dropped.
  • Rate limits: 6 live searches and 20 connection tests per minute per client.
  • Procurement CSVs are parsed in the browser and never uploaded. Files are capped at 2 MB.
  • Demo data is kept separate from live data and labelled on screen.
